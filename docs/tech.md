# 网页版 Agent 项目技术方案

## 1. 目标

构建一个可本地部署的网页版 AI Agent，支持：

- 多轮对话
- 流式输出
- 工具调用
- 任务编排
- 会话恢复
- 可扩展的代理工作流

------

## 2. 总体架构

text

```
Browser
  ↓
Next.js 前端
  ↓
assistant-ui
  ↓
LangGraph Runtime
  ↓
Python LangGraph Server
  ↓
DeepAgents / Tools / Memory / Model
```

------

## 3. 技术选型

### 3.1 前端

- **Next.js**
  - 负责页面、路由、组件组织
  - 适合网页 agent 产品
- **助手界面**
  - 负责聊天 UI、消息展示、输入交互
  - 提供可组合的 UI 原语

### 3.2 后端

- **Python**
  - 作为服务端主语言
  - 更适合 agent、工具、数据处理逻辑
- **LangGraph**
  - 负责 agent 工作流编排
  - 处理状态、分支、工具调用、多步执行
- **deepagents**
  - 作为 agent 规划/执行层
  - 用于复杂任务拆解与多步推理

### 3.3 部署

- 本地部署优先
- 支持 Docker 化
- 后续可扩展到私有化环境

## 5. 核心流程

### 5.1 聊天流程

1. 用户输入消息
2. 前端发送到后端
3. 后端进入 LangGraph
4. DeepAgents 分析任务
5. 工具执行或直接生成回答
6. 流式返回前端
7. 前端展示结果

### 5.2 会话恢复流程

1. 用户打开历史会话
2. 前端加载 thread_id
3. 后端恢复状态
4. 继续新对话

### 5.3 工具调用流程

1. 代理判断需要工具
2. 调用工具节点
3. 工具执行
4. 结果写回状态
5. 代理继续推理或输出

## 7. 接口设计建议

### 7.1 聊天接口

- `POST /chat`
- 输入：用户消息、thread_id
- 输出：回复内容或流式内容

### 7.2 会话接口

- `GET /threads`
- `POST /threads`
- `GET /threads/{id}`

### 7.3 工具接口

- `POST /tools/{name}` 或内嵌在 graph 内部
- 返回工具执行结果

## 8. 部署方案

### 8.1 本地开发

- 前端：`localhost:3000`
- 后端：`localhost:8000` 或 `localhost:2024`

### 8.2 容器化

- 前端 Docker 镜像

### 8.3 生产环境

- 可接入反向代理
- 支持环境变量配置
- 支持鉴权和日志采集

------

## 9. 风险与应对

### 9.1 流式传输不稳定

应对：

- 使用稳定的 SSE/WebSocket 方案
- 避免代理缓冲

### 9.2 状态管理复杂

应对：

- 线程ID统一管理
- 状态持久化
- 前后端职责分离

### 9.3 代理逻辑膨胀

应对：

- LangGraph 分层
- DeepAgents 作为可插拔模块
- 工具与推理解耦
