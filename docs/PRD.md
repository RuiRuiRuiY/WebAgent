# 网页版 Agent 项目 PRD

## 1. 项目概述

### 1.1 项目名称

Web Agent

### 1.2 项目目标

构建一个可本地部署的网页版 AI Agent，支持多轮对话、流式输出、工具调用、任务编排与可扩展的 agent 工作流。

### 1.3 核心场景

用户在网页中与 Agent 对话，Agent 基于 LangGraph + DeepAgents 执行多步任务，并实时返回过程与结果。

### 1.4 技术方向

- 前端：Next.js
- UI：assistant-ui
- 后端：Python + LangGraph
- 代理编排：DeepAgents
- 部署方式：本地部署 / 自托管

------

## 2. 背景与问题

当前用户需要的是一个不仅能聊天，还能：

- 理解任务目标
- 规划步骤
- 调用工具
- 维护上下文
- 持续执行复杂任务

普通聊天机器人无法很好满足这些需求，因此需要一个具备 agent 能力的网页产品。

------

## 3. 产品目标

### 3.1 业务目标

- 提供一个可用的网页 Agent 交互界面
- 支持复杂任务的逐步执行
- 支持本地部署，满足数据可控和私有化要求

### 3.2 用户目标

- 快速开始一次对话
- 清晰看到 Agent 的回复与状态
- 在需要时执行工具调用
- 保留上下文并继续任务

### 3.3 成功标准

- 用户可在网页上完成完整对话
- 代理支持流式响应
- 代理可以调用工具并返回结果
- 系统可在本地环境稳定运行

## 5. 使用场景

### 场景 1：普通对话

用户输入问题，Agent 直接回复。

### 场景 2：工具调用

用户请求查询某个信息，Agent 调用工具后给出结果。

### 场景 3：多步任务

用户提出复杂目标，Agent 自动拆分、规划、执行并总结。

### 场景 4：上下文继续

用户刷新页面后可继续之前的会话。

## 6. 功能需求

### 6.1 聊天功能

- 用户可以发送消息
- 代理可以返回消息
- 支持多轮上下文

### 6.2 流式输出

- 客服回复支持逐字/逐段流式展示

- 代理支持任务拆解
- 支持多步骤执行

### 6.6 本地部署

- 前后端可本地启动
- 支持 Docker 化部署

## 8. 产品方案

### 8.1 前端方案

- 使用 Next.js 构建网页应用
- 使用 assistant-ui 提供聊天界面
- 使用 LangGraph runtime 连接后端

### 8.2 后端方案

- 使用 Python 编写 LangGraph
- 使用 DeepAgents 处理复杂 agent 逻辑
- 对外提供流式接口和会话状态能力

### 8.3 数据流

1. 用户在网页输入消息
2. 前端通过 runtime 发送到后端
3. 后端进入 LangGraph 工作流
4. DeepAgents 进行规划/执行
5. 结果流式返回给前端
6. 前端展示回复与状态

------

------

## 10. 核心交互流程

### 10.1 发送消息

1. 用户输入消息
2. 点击发送
3. 前端提交消息
4. 后端生成回复
5. 前端流式展示结果

### 10.2 执行任务

1. 用户输入任务目标
2. 代理拆解任务
3. 代理调用工具
4. 代理汇总结果
5. 前端展示最终答案

### 10.3 恢复会话

1. 用户进入历史会话
2. 前端加载线程/会话
3. 后端恢复上下文
4. 继续新的对话

## 13. 风险与问题

### 13.1 技术风险

- 流式传输不稳定
- 工具调用状态复杂
- 会话状态管理不完善

### 13.2 体验风险

- 客服回复延迟过高
- 任务执行过程不透明
- 页面交互不够直观

### 13.3 部署风险

- 本地环境兼容性问题
- CORS/代理/流式连接配置复杂

------

## 14. 设计原则

- 先保证闭环，再增强能力
- 前端只负责展示，Agent 逻辑放在后端
- 会话状态必须可恢复
- 工具与任务流程要可追踪
- 默认支持本地部署和私有化

------

## 15. MVP 范围

### 必做

- 聊天页面
- 消息发送与回复
- Python 后端
- 基础 LangGraph
- 本地部署

### 暂不做

- 多人协作
- 复杂权限系统
- 高级可视化编排
- 多 Agent 市场化能力
